# 《一个人的 AI 团队》完整提示词

> 克劳德队长 · 2026-11 · 这条 3D 宣传片怎么做出来的，照着改题材就能用。
> 用的工具：Claude Code（写代码、统筹）+ Blender 5.2（后台渲染，免费）+ 无头浏览器 Playwright（截界面）+ Python/numpy（配乐）+ ffmpeg（合成）。没有手调一个关键帧。
> 用法：按顺序把下面 9 条提示词发给 Claude Code，每条做完、看过结果再发下一条。【】里换成你自己的内容。
> 电脑：Apple 芯片的 Mac，或带 NVIDIA 显卡的 Windows 电脑都行（Blender 分别用 Metal / OptiX 渲染）。

## 一、先想清楚：这类片子的骨架

```
开场（约 10 秒）：一句钩子 + 角色登场 + 片名
第一章：产品 / 团队怎么用（每步一个工具，角色跳过去操作）
第二章：这条片子本身是怎么做的（时间表 → 截图 → 渲染 → 配乐）
收尾：统计卡（真实数字）+ 行动号召
```

核心规则只有一条：**所有动作、镜头、字幕、音效都读同一份时间表**，按「第几小节第几拍」写，改节奏只改一个数。

## 二、第 1 条提示词：定方案（发给 Claude Code）

```
我要做一条约 100 秒的横版 3D 宣传片（1920×1080，30fps），题材是【你的题材】。
结构：开场 → 第一章（【产品】怎么用，4–5 步）→ 第二章（这条片子怎么做的）→ 统计卡 → 行动号召。
要求：
1. 用 Blender 后台渲染，场景、角色、镜头全部由 Python 代码生成，不手调关键帧。
2. 屏幕上的界面用 HTML 写，逐帧截图贴到 3D 屏幕上。
3. 全片按 BPM 走（先用 116），每个动作落在拍子上。
4. 片子里的功能和数字只写真实做到的，做不到的不写；拿不准的先列出来问我。
先给我：方案（每一章演什么）、角色设定、每步要展示的真实能力和依据。不要开始写代码。
```

## 三、第 2 条：搭时间表（唯一真值）

```
按刚才的方案写 timeline.py：
- BPM、FPS 放最前面；at(小节, 拍) 换算成秒。
- 每个角色一串动作：跳（起拍、落拍、落到哪个格子）、原地蹦、砸、钻进屏幕。
- 镜头是一串关键机位（时刻、位置、看向），用样条连起来，速度不归零；飞行段跟拍角色。
- 字幕、数据卡、步骤名都写在这里。
导出 timeline.json，后面的网页、Blender、配乐都只读它。
```

## 四、第 3 条：「格子」系统（让每一跳都有交代）

```
每个工具前面放一个图标格子，工具之间铺一排踏板格子。
屏幕里的东西也定义成格子（任务卡、文件标签、审查项、设备），用像素坐标写，同一份坐标换算成 3D。
角色一拍跳一格；落到哪格，哪格就压一下再弹起、发光，并出一个音。
第一次有人跳上图标，这个工具的屏幕才亮。
```

## 五、第 4 条：界面页

```
写 ui/screens.html：每个工位一页（?s=页面名），window.renderAt(t) 画出 t 秒时的样子。
界面照真实系统重画，内网地址、账号不上屏；代码屏显示真实源码（截图时读入，去掉注释）。
再写 shoot.mjs：用无头浏览器逐帧截图，文件名 = 帧号。
```

## 六、第 5 条：Blender 场景

```
写 scene.py，用法：blender -b -P scene.py -- <贴图目录> <输出目录> <起始帧> <结束帧> [--preview]
- 桌面、平板（屏幕贴图用图像序列做自发光）、角色（体素小方块，身体 + 手 + 腿）。
- 每帧调用时间函数算出角色位置、旋转、挤压，写成关键帧（代码算的，不是手 K 的）。
- 跳跃 = 抛物线 + 起跳拉长 + 落地回弹；起跳前下蹲。
- 后期加泛光，阈值调高，只让真正发光的东西起光晕。
- --preview：半分辨率、16 采样，先看节奏；定稿再 64 采样全分辨率。
```

## 七、第 6 条：配乐和音效

```
写 score.py，用 numpy 合成（不依赖外部素材）：鼓、贝斯、铺底、铃铛、木琴。
所有时间点从 timeline.json 取：每次落格出一个音（踏板铃铛逐级升高、图标"啵"+和弦、界面格子木琴），
砸下去一锤，转场上行扫频。响度做到约 −14 LUFS，峰值不超过 −1 dB。
```

## 八、第 7 条：字幕层

```
写 ui/overlay.html：透明底、1920×1080，同样用 renderAt(t)。
放片名、章节卡、步骤名（先大字 2 拍，再缩到左上角当进度条）、底部字幕、数据卡、片尾行动号召。
大字下面垫一层暗渐变，避开背后屏幕上的字。截图时保留透明通道，最后叠在 3D 画面上。
```

## 九、第 8 条：预览 → 正式渲染 → 合成

```
写一个构建脚本：
1. 截所有界面页和字幕层（并行）；
2. Blender 分段渲染（每段几十帧，已有的帧跳过，断了能续）；先出低清预览看节奏和故事，确认后再正式渲染；
3. 有多台电脑就做成"领活"队列：每台渲完一段自动领下一段，快的多渲；
4. 配乐按全片长度生成；
5. ffmpeg 把 3D 帧 + 字幕层 + 配乐合成 mp4。
```

## 十、第 9 条：自检和逐帧验收

```
每改一轮，抽 10 帧拼成一张图给我看；
检查：角色有没有出画、字幕有没有挡住界面、屏幕反光有没有盖住字、上屏数字是不是今天现查的。
正式渲染后先逐帧核对再合成：帧号连续不缺、每张都能完整解码、尺寸对、没有贴图丢失的粉屏、字幕层齐全；
再算相邻两帧的亮度差，突变的地方逐个看图，分清是设计的动作还是镜头跳。有一项不过就不合成。
```

## 踩过的坑（省你时间）

- **太快看不清**：128 BPM 下角色原地转 5 圈，画面糊成一团；降到 116 BPM、转 4 圈刚好。
- **屏幕反光**：屏幕材质要偏哑光（粗糙度 0.3 左右），否则灯一打字就看不见。
- **浅色界面发白**：浅色页面的自发光强度要减半。
- **注释会上屏**：代码屏显示源码时要去掉注释，里面常有内部备注。
- **统计卡别写死**：行数、帧数在构建时现数。
- **时间别写死成秒**：改了 BPM，写死的秒数不会跟着变，镜头会在那里跳一下。所有时间都用「第几小节第几拍」算。
- **场景不能随渲染范围变**：如果脚本按"这次渲到第几帧"决定搭不搭某些东西，分段渲染的接缝处画面会突变。场景每次都完整搭。
- **从 Mac 拷文件到 Windows**：打包要加 `COPYFILE_DISABLE=1`，否则会带进 `._` 开头的隐藏文件，Blender 把它当贴图，屏幕整片发粉。
